By default Claude Code adds attribution to the commits and pull requests it creates. The `attribution` setting customizes or hides it. It can live in any settings file. This repo sets it in `.claude/settings.json`, because a cloud session reads only what is in the clone, and the official documentation says that to change a setting for a single-repo session you commit the key in that repo's `.claude/settings.json`.

```json
{
  "attribution": {
    "commit": "",
    "pr": "",
    "sessionUrl": false
  }
}
```

| Key | Type | What it controls |
| :- | :- | :- |
| `attribution.commit` | string | Changes or hides the trailer Claude Code adds to commit messages. `""` hides it |
| `attribution.pr` | string | Changes or hides the attribution line in the description of pull requests. `""` hides it |
| `attribution.sessionUrl` | boolean | Whether commits from the cloud and from Remote Control include the link to the claude.ai session. `false` omits it |

:::note
The older `includeCoAuthoredBy` setting is deprecated. `attribution` replaces it.
:::

## What it does not cover

- **The git author and committer identity.** `attribution.commit` only controls the trailer of the message. The name and email of the commit come from the git identity: see [Environment variables](/en/configuracion/variables-de-entorno/).
- **The footer added to PR bodies.** The official documentation does not describe it.

:::note[Observation]
With `attribution.pr` set to `""`, a "Generated by Claude Code" footer was still added to the PR body, both when creating and when editing PRs. With the `/web-setup` connection it kept being added on creation. How to remove it is in [Remove the attribution footer](/en/workflow/pie-de-atribucion/).
:::
