El loop corre en una sesión en la nube y lleva un issue hasta un pull request listo para revisar. La sesión actúa como orquestadora: despacha cada etapa por nombre con una instrucción de una línea y no implementa nada.

<LoopFlow />

Si algo falla, [Recuperación](/workflow/recuperacion/) dice qué hacer en cada caso.

:::tip
Revisá el PR antes de mergear. El loop lo deja listo; el merge siempre lo decide una persona.
:::

## Por qué las reglas se aplican con código

`CLAUDE.md` fija las reglas de ramas, commits y pull requests, y cada sesión en la nube lo carga. Pero las instrucciones son consejos: una sesión puede interpretarlas mal, olvidarlas después de una conversación larga o seguir una instrucción del entorno que las contradice, como el nombre de rama al que se le dice que pushee. Un script no se deja convencer de saltarse un chequeo. `scripts/ship.sh` y `scripts/issue.sh` convierten cada regla en una prueba que pasa o frena la ejecución con un mensaje. Así, una sesión que sigue `CLAUDE.md` y una que no terminan con la misma rama, el mismo mensaje de commit y la misma forma de PR.
