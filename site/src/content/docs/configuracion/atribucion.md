Por defecto Claude Code agrega atribución a los commits y pull requests que crea. El ajuste `attribution` la personaliza o la oculta. Puede vivir en cualquier archivo de settings. Este repo lo fija en `.claude/settings.json`, porque una sesión en la nube lee solo lo que hay en el clon, y la documentación oficial indica que para cambiar un ajuste de una sesión con un solo repo se commitea la clave en el `.claude/settings.json` de ese repo.

```json
{
  "attribution": {
    "commit": "",
    "pr": "",
    "sessionUrl": false
  }
}
```

| Clave | Tipo | Qué controla |
| :- | :- | :- |
| `attribution.commit` | string | Cambia u oculta el trailer que Claude Code agrega a los mensajes de commit. `""` lo oculta |
| `attribution.pr` | string | Cambia u oculta la línea de atribución en la descripción de los pull requests. `""` la oculta |
| `attribution.sessionUrl` | boolean | Si los commits de la nube y de Remote Control incluyen el link a la sesión de claude.ai. `false` lo omite |

:::note
El ajuste anterior `includeCoAuthoredBy` está obsoleto. `attribution` lo reemplaza.
:::

## Lo que no cubre

- **La identidad de autor y committer de git.** `attribution.commit` solo controla el trailer del mensaje. El nombre y el email del commit salen de la identidad de git: ver [Variables de entorno](/configuracion/variables-de-entorno/).
- **El pie que se agrega a los cuerpos de los PRs.** La documentación oficial no lo describe.

:::note[Observación]
Con `attribution.pr` en `""`, igual se agregó un pie "Generated by Claude Code" al cuerpo de los PRs, tanto al crearlos como al editarlos. Con la conexión por `/web-setup` se siguió agregando al crear. Cómo quitarlo está en [Quitar el pie de atribución](/workflow/pie-de-atribucion/).
:::
